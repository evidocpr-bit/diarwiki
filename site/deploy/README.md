# Развёртывание «ДиарВики»

## Предварительные условия

1. Публичная A-запись `diarwiki.ru` возвращает IP сервера.
2. Порты 80 и 443 доступны извне.
3. SSH-ключ загружен в агент: `ssh-add $env:USERPROFILE\.ssh\diarwiki_ed25519`.
4. Известен реально работающий адрес редакции и адрес владельца для уведомлений ACME.

## Первичная подготовка сервера

Каталог `deploy` копируется во временный каталог сервера. Затем от root выполняется `bootstrap-server.sh`. После проверки скрипты активации и отката устанавливаются как:

```text
/usr/local/sbin/diarwiki-activate
/usr/local/sbin/diarwiki-rollback
```

Caddy запускается во время подготовки сервера. До загрузки первого релиза он может отвечать ошибкой 404, а сертификат получит автоматически, как только публичная DNS-запись начнёт вести на сервер. Адрес для уведомлений ACME можно добавить позднее через глобальную настройку `email` в Caddyfile, но для автоматического выпуска сертификата он не обязателен.

## Публикация

Из каталога `site`:

```powershell
.\deploy\publish.ps1 -HostName 'адрес-сервера' -EditorEmail 'рабочий-адрес-редакции'
```

Скрипт работает только с чистым, уже зафиксированным в Git каталогом `site`. Он запускает тесты и сборку с открытой индексацией, создаёт `release.json`, считает SHA-256 архива и атомарно переключает `/srv/diarwiki/current`.

После активации сервер проверяет публичный HTTPS и постоянные адреса без параметров: главную, `/about/`, начало, базу знаний и конвертер. Проверка подтверждает правовые страницы, партнёрскую формулировку, заголовки кеша, CSP с поддержкой Pagefind и идентификатор выпуска. При ошибке скрипт записывает результат и возвращает предыдущий выпуск. Серверная проверка не зависит от сетевого маршрута компьютера, с которого запущена публикация.

Журнал `/srv/diarwiki/shared/releases.log` хранит активации, контрольные суммы, предыдущие версии, результаты проверки и откаты. Текущий выпуск можно посмотреть по адресу `https://diarwiki.ru/release.json`; этот ответ не кешируется.

## Кеширование

- HTML: `no-cache, max-age=0, must-revalidate`;
- `/release.json`: `no-store`;
- `/_astro/*`: год с директивой `immutable`;
- `/pagefind/*`: `no-cache, max-age=0, must-revalidate`, поскольку имена файлов Pagefind не все содержат версию;
- `/robots.txt`: пять минут.

После изменения Caddyfile сначала выполните `caddy validate --config /etc/caddy/Caddyfile`, затем перезагрузите Caddy. Не используйте временные параметры в публичных ссылках для обхода кеша.

## Проверка SSL/TLS

После запуска Caddy требуется проверить:

- `http://diarwiki.ru` перенаправляет на `https://diarwiki.ru`;
- сертификат доверенный и выписан на `diarwiki.ru`;
- срок действия корректен;
- `systemctl status caddy` активен;
- в `journalctl -u caddy` нет ошибок выпуска или продления;
- тестовое `caddy renew --force` не используется без причины: автоматическое продление проверяется по журналу и таймерам службы.

`www.diarwiki.ru` не добавляется в Caddyfile, пока для него не создана публичная DNS-запись. Это предотвращает ошибку выпуска сертификата для несуществующего имени.
