# Реестр подтверждений врачебной рецензии

Для каждого материала со статусом `medicalReview: reviewed` создайте `<contentId>.json` по шаблону:

```json
{
  "contentId": "DW-CGM-BASICS",
  "contentPath": "knowledge/cgm-basics.mdx",
  "contentHash": "<SHA-256 из reviewedContentHash>",
  "reviewerName": "Имя специалиста с его согласия на публикацию",
  "reviewerSpecialty": "Специальность",
  "reviewerProfileUrl": null,
  "reviewedAt": "ГГГГ-ММ-ДД",
  "evidenceType": "email-confirmation",
  "evidenceRef": "<нечувствительный идентификатор записи во внутреннем хранилище>",
  "approvedBy": "site-owner",
  "approvedAt": "ГГГГ-ММ-ДД"
}
```

`contentId`, `contentPath`, хэш, сведения о рецензенте и дата должны совпадать с материалом. Строки рецензионных полей исключены из отпечатка, поэтому hash можно вычислить до или после добавления `reviewerSpecialty` и остальных полей проверки. Сборочная проверка подтверждает только согласованность этого журнала с файлами проекта; она не подтверждает подлинность согласия или квалификацию врача. Исходные письма, скриншоты, подписи, персональные данные и медицинские данные не коммитить — хранить ограниченно доступно, а здесь указывать только безопасный идентификатор.

Перед изменением статуса владелец проекта вручную проверяет подтверждение, согласие на публикацию имени и профиля, личность/специальность и точную версию статьи. Изменения `reviewed` должны попадать в защищённую ветку только после одобрения владельца репозитория в CI-хостинге. Настройки такого контроля зависят от выбранного Git-хостинга и не заменяются этой локальной проверкой.

Пока версионный хэш покрывает MDX/frontmatter, но не бинарные изображения, файлы из `public/` и общие JSON-файлы источников. Любое изменение такой связанной зависимости требует снять отметку и повторить проверку вручную.
