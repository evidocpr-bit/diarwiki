# Проверка безопасности: 2 ноября 2026

Проверены публичный репозиторий `evidocpr-bit/diarwiki`, его исходная история из трёх коммитов, зависимости сайта и двух расширений CMS. После исправлений выполнен повторный проход по подготовленной версии. Рабочий сервер и его секреты не изменялись. Это техническая проверка исходников, а не сертификация безопасности или проверка медицинской достоверности.

## Проход 1: исходное состояние

- Gitleaks 8.30.1 проверил все три исходных коммита: совпадений с правилами поиска секретов нет. Архив инструмента получен из официального релиза, SHA-256 сверена с опубликованным списком.
- Аудит сайта: 2 low и 3 moderate; high/critical не обнаружены.
- Аудит каждого расширения CMS: 3 low, 3 moderate, 5 high; critical не обнаружены. Замечания относились к дереву инструментов сборки.
- В шести шаблонах JSON-LD использовался прямой `JSON.stringify` внутри HTML script. При появлении закрывающего тега в данных это допускает выход из блока.
- GitHub Actions ссылался на изменяемые теги внешних действий. Checkout по умолчанию сохранял учётные данные в рабочей копии.
- Граф зависимостей, Dependabot alerts/security updates и приватные сообщения об уязвимостях были выключены. Secret Protection и Push protection уже были включены.

## Что исправлено

- Добавлена общая функция `serializeJsonLd`: опасные для HTML-контекста символы экранируются, а данные остаются корректным JSON. Все шесть шаблонов используют её. Добавлен тест с закрывающим тегом script и проверкой восстановления исходных данных.
- Обновлены уязвимые транзитивные зависимости. Для CMS закреплены исправленные Vite 8.1.6, Zod 4.6.6 и Joi 18.3.1; совместимость проверена типизацией и сборкой обоих расширений.
- Внешние Actions закреплены по полным SHA; у checkout установлено `persist-credentials: false`. Workflow имеет `contents: read`, лимит времени, проверку зависимостей и еженедельный запуск. Привилегированный `pull_request_target` не используется.
- Добавлены Dependabot configuration, CODEOWNERS и исключения для локальных ключей, баз данных, дампов и файлов конфигурации.
- Включены граф зависимостей, Dependabot alerts, security updates, malware alerts, приватные сообщения и CodeQL для JavaScript/TypeScript и GitHub Actions. Автоматическое слияние обновлений не настроено.

Закрепление действий по SHA и минимальные разрешения соответствуют [рекомендациям GitHub](https://docs.github.com/en/actions/reference/security/secure-use). [Приватные сообщения](https://github.com/evidocpr-bit/diarwiki/security/advisories/new) предназначены для деталей, которые нельзя помещать в открытый Issue.

## Дополнительные результаты CodeQL

Первый серверный анализ выявил три предупреждения в служебных скриптах SEO и IndexNow: два случая последовательного декодирования сущностей и фильтрацию HTML регулярным выражением. Декодирование заменено одним проходом с callback, подсчёт видимого текста — разбором через sanitize-html. Добавлены проверки вложенного экранирования и содержимого script/style. Эти скрипты не являются пользовательскими HTTP-обработчиками, но их обработка данных также должна быть корректной.

## Оставшееся замечание

В каждом расширении остаётся `deepmerge@4.3.1`, транзитивная зависимость `@rollup/plugin-node-resolve` в SDK сборки Directus. [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) имеет уровень low; исправленной версии в advisory на дату проверки нет. Проблема позволяет изменять прототип возвращаемого объекта через специально подготовленные данные.

По установленному дереву зависимостей пакет относится к devDependencies сборки расширения; он не входит в зависимости публичного Astro-сайта. Это ограничивает область риска, но не доказывает невозможность эксплуатации. Сборку следует выполнять в изолированном окружении без production-секретов. Замечание не скрыто через `audit.ignore`; CI выводит его, а для расширений блокирует high/critical. Для сайта блокируется любой уровень от low.

## Границы проверки

- Не выполнялся пентест рабочего сервера, проверка его пользователей, SSH, резервных копий и фактической конфигурации Caddy/Directus.
- Конфигурация CSP допускает inline-скрипты и Яндекс Метрику. Удалять эти разрешения без проверки функциональности нельзя; более строгая политика с хэшами или nonce требует отдельной работы с выпуском сайта.
- Фильтр SVG и проверка сигнатур медиа не равнозначны антивирусу или полноценной проверке всех форматов. Загрузка недоверенных файлов требует отдельной приёмки CMS и инфраструктуры.
- Gitleaks и CodeQL покрывают определённые классы ошибок; отсутствие находок не доказывает отсутствия всех секретов и уязвимостей.
- Браузерный набор e2e в рамках этой проверки не запускался. Проверены модульные тесты, типы, сборка и статические контракты.
