# DiarWiki Workflow

Серверное расширение Directus для правил редакционного процесса. Ограничения действуют на API, а не только на кнопки панели.

## Что защищает расширение

- проверяет допустимые переходы статусов;
- получает возможности пользователя из назначенных политик, поэтому права можно переносить между ролями;
- требует актуальную медицинскую рецензию для настроенных уровней риска;
- связывает рецензию с SHA-256 нормализованного публичного набора;
- отзывает рецензию после изменения материала, блока, источника, связи или медиа;
- запрещает самостоятельную выдачу политик `owner-admin` и `content-publish`;
- не позволяет удалить, заблокировать или лишить доступа всех владельцев;
- пишет структурированные события для критических операций без содержимого статей и секретов.

Владелец с политикой `content-publish` создаёт запрос выпуска. Переход `ready_to_publish → published` выполняет только политика `release-service` после успешной технической проверки выпуска.

## Локальная проверка

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm run typecheck
pnpm run build
```

Собранный `dist/index.js` загружается Directus из каталога `/directus/extensions/diarwiki-workflow`. После первого запуска на стенде нужно выполнить интеграционные проверки каждой роли через API и проверить журнал Directus.

## Настраиваемость медицинской проверки

В singleton-коллекции `site_settings` поле `medical_review_required_risks` содержит массив уровней риска. Начальное значение — `["high"]`. Высокий риск в любом случае остаётся обязательным на уровне серверного правила.
