# Начальная настройка доступа Directus

Файлы `roles.json` и `policies.json` задают только начальную безопасную матрицу. После запуска владелец сможет создавать дополнительные роли и назначать политики через интерфейс Directus.

## Предварительная проверка

```powershell
node .\cms\bootstrap\apply-access.mjs
node --test .\cms\tests\access-matrix.test.mjs
```

Без `--apply` сценарий не обращается к Directus и ничего не изменяет.

## Применение к тестовому экземпляру

Административный токен передаётся только через переменную процесса:

```powershell
$env:DIRECTUS_BOOTSTRAP_TOKEN = 'временный-токен'
node .\cms\bootstrap\apply-access.mjs --apply --url http://127.0.0.1:8055
node .\cms\bootstrap\verify-access.mjs --url http://127.0.0.1:8055
Remove-Item Env:DIRECTUS_BOOTSTRAP_TOKEN
```

Сценарий синхронизирует только роли и политики с меткой `[diarwiki:...]`. Внутри управляемой политики лишнее разрешение удаляется, чтобы старое правило не оставило скрытое расширение доступа. Пользователи, пароли, токены и назначения участников не создаются.

Применение сначала выполняется на staging. После него доступ каждой роли проверяется отдельной тестовой учётной записью через API.

## Настройка Directus Studio

После создания схемы и применения ролей выполняется настройка русских названий, форм, очередей и дашборда:

```powershell
node .\cms\bootstrap\apply-studio.mjs
node .\cms\bootstrap\apply-studio.mjs --apply --url http://127.0.0.1:8055
```

Команда без `--apply` только проверяет локальные манифесты. Подробное описание рабочего интерфейса находится в [editorial-ui.md](../docs/editorial-ui.md).
