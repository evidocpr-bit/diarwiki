# Предварительная проверка CMS «ДиарВики»

Дата фиксации: 22 октября 2026 года.

## 1. Лицензия Directus

Для разработки зафиксирован Directus `12.5.0`. Directus 12 использует активную проверку лицензии; часть расширенных возможностей, включая пользовательские правила политик, требует подходящего ключа. Модель доступа «ДиарВики» использует такие правила, поэтому рабочий запуск нельзя выполнять без подтверждения лицензии.

До production необходимо выполнить одно из условий:

- получить Open Innovation Grant, если владелец и организация соответствуют действующим условиям Directus;
- приобрести коммерческую лицензию;
- письменно изменить архитектуру и отказаться от функций, которым требуется лицензия.

Актуальные условия сверяются перед рабочим запуском:

- <https://github.com/directus/directus/releases>;
- <https://github.com/directus/directus/blob/main/directus/license>;
- <https://directus.io/pricing/>.

Лицензионный ключ хранится только в защищённом окружении сервера. Он не добавляется в Git и не включается в резервные копии содержимого.

## 2. Состояние локального компьютера

Проверено 22 октября 2026 года:

- Node.js `24.20.0` доступен;
- pnpm `11.25.0` доступен;
- Docker CLI и Docker Compose не установлены.

Отсутствие Docker не мешает создавать и тестировать независимые сценарии, схему, генератор снимков и интеграцию Astro. Полный стек Directus и PostgreSQL требуется запускать на отдельном тестовом сервере или после явной установки Docker.

## 3. Проверка сервера до установки

Необходимо собрать и сохранить фактические результаты:

- версия ОС и доступные обновления безопасности;
- число vCPU, объём RAM и swap;
- свободное место, файловая система и рост существующих выпусков;
- наличие Docker Engine и Compose;
- состояние Caddy и занятые порты;
- текущие службы и контейнеры;
- доступность DNS для `cms.diarwiki.ru` и `preview.diarwiki.ru`;
- возможность хранить резервную копию вне сервера;
- правила firewall и отсутствие публичного PostgreSQL;
- действующий пользователь публикации и его минимальные полномочия.

Проверка является только чтением. Установка пакетов, изменение DNS, Caddy, firewall или production-служб выполняются после локальной подготовки конфигурации и тестового запуска.

## 4. Окружения

### Development

- адрес `http://127.0.0.1:8055`;
- тестовые данные;
- допускается отсутствие лицензионного ключа только для функций, доступных в Core;
- письма не уходят реальным получателям.

### Staging

- отдельная база и хранилище файлов;
- доступ ограничен;
- используются копии структуры, но не реальные пароли и подтверждения;
- проверяются роли, 2FA, миграция, публикация, откат и восстановление.

### Production

- адрес `https://cms.diarwiki.ru`;
- обязательные HTTPS, 2FA, рабочий лицензионный ключ и SMTP;
- PostgreSQL недоступен извне;
- резервная копия хранится вне текущего сервера;
- переключение выполняется только после сквозной приёмки staging.

## 5. Стоп-условия

Рабочая установка не начинается, если:

- лицензионный режим не подтверждён;
- нет проверяемой резервной копии;
- серверу не хватает ресурсов с безопасным запасом;
- PostgreSQL планируется открыть в интернет;
- невозможно обеспечить 2FA владельцу;
- отсутствует способ отката публичного сайта;
- миграция меняет существующие `contentId` или публичные адреса без утверждённых перенаправлений.
