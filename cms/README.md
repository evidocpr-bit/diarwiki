# CMS «ДиарВики»

Закрытая редакционная система на Directus и PostgreSQL. Публичный `diarwiki.ru` остаётся статическим сайтом Astro и не читает данные из CMS во время запроса посетителя.

Основание:

- [дизайн CMS](../docs/superpowers/specs/2026-10-22-diarwiki-cms-design.md);
- [план реализации](../docs/superpowers/plans/2026-10-22-diarwiki-cms-implementation.md).

## Текущее состояние

Локально реализованы модель данных, изменяемые политики ролей, русский интерфейс, серверные правила процесса, безопасное медиа, миграция, предпросмотр, неизменяемые снимки, генератор Astro, атомарный выпуск с откатом и серверные сценарии резервирования. Результаты приёмки и внешние блокирующие условия находятся в `output/Проверка CMS DiarWiki/`.

Рабочий сайт намеренно ещё не переключён на CMS: на текущем компьютере нет Docker, production-сервер и рабочий Directus не подключены, лицензия и 2FA владельца не подтверждены, а у девяти перенесённых иллюстраций ожидается подтверждение прав. До выполнения этих условий действующие MDX-файлы остаются источником публичного содержимого.

## Проверка шаблона

```powershell
node .\cms\scripts\check-env.mjs --env .\cms\.env.example --example
node --test .\cms\tests\check-env.test.mjs
```

Проверка выводит только названия проблемных переменных и никогда не печатает их значения.

## Подготовка локального окружения

1. Скопировать `.env.example` в `.env`.
2. Сгенерировать уникальные секреты отдельным скриптом следующего этапа.
3. Указать реальный адрес владельца и SMTP-настройки.
4. Для рабочего запуска указать подходящий лицензионный ключ Directus.
5. Запустить проверку без `--example`.

Файл `.env` исключён из Git. Пароли, токены, ключ лицензии и коды двухфакторной аутентификации нельзя помещать в исходники, журналы и снимки содержимого.

## Версии

- Directus: `12.5.0`, точный тег образа;
- PostgreSQL: ветка `17-alpine`, обновляемая только после резервной копии и проверки восстановления;
- Node.js для служебных сценариев: текущая поддерживаемая версия проекта, на момент начала работ локально проверена `24.20.0`.

## Контейнерное окружение

После заполнения `.env`:

```powershell
node .\cms\scripts\check-env.mjs --env .\cms\.env
node .\cms\scripts\validate-compose.mjs .\cms\compose.yaml
docker compose --env-file .\cms\.env -f .\cms\compose.yaml config
docker compose --env-file .\cms\.env -f .\cms\compose.yaml up -d
node .\cms\healthcheck.mjs http://127.0.0.1:8055
```

## Серверные правила процесса

Расширение `extensions/diarwiki-workflow` управляет переходами статусов, медицинскими отпечатками, отзывом устаревшей рецензии и защитой владельца. Оно собирается отдельно до запуска контейнеров; команды и модель полномочий описаны в [README расширения](extensions/diarwiki-workflow/README.md).

Содержимое передаётся в Astro только через [неизменяемый снимок выпуска](release/README.md). Его контрольная сумма проверяется до генерации сайта.

PostgreSQL не публикует порт на хосте. Directus слушает только `127.0.0.1:8055`; внешний HTTPS позже будет принимать Caddy. На текущем рабочем компьютере Docker не установлен, поэтому команды `docker compose` должны выполняться в подготовленном тестовом окружении.
