# Неизменяемые снимки DiarWiki

Снимок — единственный вход содержимого в сборку публичного Astro-сайта. Публичный сайт не читает Directus во время запроса посетителя.

## Свойства

- одинаковые нормализованные данные дают одинаковый JSON и SHA-256;
- ключи объектов, Unicode, переносы строк и даты приводятся к устойчивому виду;
- коллекции сортируются по стабильным идентификаторам, блоки — по порядку;
- черновики, неподтверждённые ссылки и непроверенные медиа не проходят границу выпуска;
- высокий риск требует одобренной медицинской рецензии с тем же отпечатком;
- `snapshot_id` выводится из полного SHA-256;
- файл создаётся с флагом `wx`, поэтому существующий снимок нельзя перезаписать.

## Создание и проверка

```powershell
node .\cms\release\create-snapshot.mjs --input .\release-input.json --output .\cms\snapshots\release.json
node .\cms\release\verify-snapshot.mjs .\cms\snapshots\release.json
```

Входной JSON формирует служба выпуска из Directus. В нём находятся выбранные готовые материалы, уже опубликованные материалы и все разрешённые зависимости. Сам модуль снимка не хранит токены и не обращается в сеть.

## Автоматический выпуск

`run-release.mjs` под единственной файловой блокировкой забирает первый запрос со статусом `queued`, создаёт снимок, собирает сайт в чистом каталоге, запускает тесты и связывает архив с манифестом контрольными суммами. Затем он атомарно переключает `/srv/diarwiki/current`, проверяет HTTPS-версию и только после этого записывает результат в CMS. Ошибка после попытки активации приводит к возврату на предыдущий выпуск. Повторный запрос ограничен `RELEASE_MAX_ATTEMPTS`.

Служебная учётная запись получает только политику `release-service`, не входит в Studio и читает секрет из `/etc/diarwiki/release.env`. Обязательные переменные:

```dotenv
DIRECTUS_URL=http://127.0.0.1:8055
RELEASE_SERVICE_TOKEN=<service-token>
RELEASE_LOCK_FILE=/var/lib/diarwiki-release/release.lock
RELEASE_WORK_ROOT=/var/lib/diarwiki-release
RELEASE_SITE_SOURCE=/opt/diarwiki/site
RELEASE_SITE_ROOT=/srv/diarwiki
RELEASE_MAX_ATTEMPTS=3
```

Установка таймера выполняется копированием `release-worker.service` и `release-worker.timer` в `/etc/systemd/system/`, после чего включается только таймер. Запуск от root не требуется; пользователю `diarwiki-release` нужны запись в каталоги выпуска и право выполнять строго ограниченные скрипты активации.

Схема формата находится в `snapshot-schema.json`. Изменение несовместимого формата требует нового `schema_version`.
